
# Preface: Human Contributions Preferred for Specs and Tests

We primarily want contributions from humans for the specifications (specs) and the tests. While automation and AI can assist, the most valuable input for these areas comes from thoughtful human contributors who can provide insight, context, and creativity.

If you are interested in helping with specs or tests, your human perspective is especially welcome!

# Contributing to JustUse
Hi! Thank you for your interest in contributing to justuse :)

Besides tackling [good first issues](https://github.com/amogorkon/justuse/issues?q=is%3Aopen+is%3Aissue+label%3A%22good+first+issue%22), there is plenty other stuff to do - like writing unit tests and documentation, finding bugs and report them or coming up with new ideas and questions to keep us on our toes.

For general ideas and questions, you can use [github discussions](https://github.com/amogorkon/justuse/discussions), for documentation please refer to our [wiki](https://github.com/amogorkon/justuse/wiki) and for discussions regarding code, and always feel free to join our [slack channel](https://app.slack.com/client/T0297SNMCHY).

If you want to contribute code, be aware that I enforce proper code formatting via automation (ruff) with 120 characters per line and 4 spaces indentation.
You can use any formatting style you like on your side, I don't care - just don't complain if they get mangled to 4-space indentation.
I (some might say excessively) use AI tools for code completion, review and refactoring, so I understand if you do too, but please don't rely on them, especially for specs and tests, as they MUST be reviewed by a human for correctness and sanity. With that said, I also don't care if you code golf or use AI tools to generate code, as long as the code is correct. It will be automatically formatted and reviewed so don't worry about form or commenting too much.

To streamline commit messages, automatically managing issues and making them generally more useful for debugging, please follow [How to write good commit Messages](https://chiamakaikeanyi.dev/how-to-write-good-git-commit-messages/)


Well, that's it. Welcome aboard!
